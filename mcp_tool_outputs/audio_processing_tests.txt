=== Audio Processing Test Results ===
Date: 2024-01-29
Session: Audio processing pipeline overhaul

OBJECTIVE:
Fix audio processing to properly handle various audio array shapes following industry conventions.

ISSUES FIXED:
1. Window shape dimension mismatch in VAD processing
2. Resampled audio shape errors (1, samples) instead of (samples,)
3. Generation kwargs None value error
4. Inconsistent channel handling across different decoder backends

RESEARCH FINDINGS:
- soundfile: Returns (samples, channels) - channels-last format
- torchaudio: Returns (channels, samples) - channels-first format  
- librosa: Returns (channels, samples) for multichannel
- np.ascontiguousarray() required after transpose for C-contiguous memory

SOLUTIONS IMPLEMENTED:
1. Rewrote ensure_mono() with intelligent channel detection:
   - Uses heuristic: channels dimension typically <=16, samples >> channels
   - Handles both channel-first (channels, samples) and channel-last (samples, channels)
   - Properly averages across correct dimension
   - Returns C-contiguous 1D array

2. Fixed resample_audio():
   - Converts to mono first via ensure_mono()
   - Handles torchaudio tensor format (1, samples)
   - Squeezes output to 1D (samples,)
   - Ensures float32 dtype

3. Updated prepare_audio():
   - Added defensive validation at each stage
   - Ensures 1D output throughout pipeline
   - Validates final output shape

4. Fixed decoder backends:
   - _decode_with_soundfile(): Documented (samples, channels) format
   - _decode_with_torchaudio(): Squeezes mono (1, samples) to (samples,)
   - _decode_with_pydub(): Reshapes to (samples, channels), handles mono
